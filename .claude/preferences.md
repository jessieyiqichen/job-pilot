## 2. 话术习惯（写简历 / 文案 / 给建议时）

- **中文交流**
- **拒绝 buzzword**：不堆名词（"eval 框架/资产库/多 Agent 协作"这类），每句话都要能扛住面试官追问
- **讲人话、讲实话**：简历 bullet 要讲面试官听得懂的东西——成本、可靠性、踩过的 LLM 坑及解决方式，而不是抽象工程词
- **不夸大**：没在团队用过就不说"团队可复用"；没做的事不写
- **给建议的结构**：先给明确判断 / 推荐方案（带"推荐"标注），再展开理由，最后留一个可追问的反问
- **PM 视角优先**：技术亮点按"PM 相关度 × 一句话能讲清"排序
- **决策时简短放权**："好""继续""按你想法""做吧"——这是信任你判断、让你拍板推进，不是敷衍。但**遇到 ta 的专业领域（简历话术、打招呼 style guide、求职策略）会突然给很细的规则**——这时按 ta 给的规则逐条执行，别自由发挥。
- 偶尔语音输入（句子较长、有口语连写），抓意图别抠字面。
- **要真话，哪怕扎心**：ta 明确奖励"删掉这条 buzzword""demo 只覆盖三成""你这个 agent 白干了"这种直说。报喜不报忧 = 失分。

## 3. 你怎么想（思维与决策风格）

> 我（agent）从长期协作观察到的，用来更好地配合 ta，不是评判。如有出入 ta 直接改。

- **建造者本能**：享受把东西做出来、ship 功能；产出快、迭代猛。**但要警惕"造工具上瘾"**——有时造工具比用工具更爽，对求职者是时间风险。我该在合适时机提醒"该停下来用了"。
- **具体 > 抽象**：判断标准是"扛得住面试官追问吗"。讨厌空话、名词堆砌、AI 模板味。
- **诚实/合规优先**：愿意为"不自动投递、不自爬、低风险"做取舍，把克制当成熟而非短板。
- **产品视角**：会想北极星指标、ROI、用户（自己 dogfooding）痛点；先做闭环再做演示。
- **重度用 Claude Code 独立从 0 到 1**：Nous / MusiClaw / JobPilot 三个独立项目都是这么搭的，"AI 辅助开发"（人主导），不是"vibe coding"（隐含 AI 替 ta 想）。

## 4. 工作 workflow 习惯

- **跨 session 交接强制**：每完成一个任务立即更新 `.claude/handoff.md`（标 ✅ + 写完成报告）；不更新 = 任务未完成。session 结束 commit & push
- **先写测试再实现**（TDD，80%+ 覆盖）
- **代码约定**：frozen dataclass（不可变）、connection-per-call SQLite、adapter 模式隔离平台、文件 <800 行、不做爬虫
- **AI 可选降级**：无 API key 时走启发式，不影响基本功能
