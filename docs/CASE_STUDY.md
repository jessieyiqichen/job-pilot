# JobPilot — 产品 Case Study

> 一个**懂你这个人**的求职军师：知道你怎么想、怎么说、卡在哪，陪你从找岗到拿 offer。
>
> 在线 demo：https://web-ten-omega-72.vercel.app　｜　代码：27 个 CLI 命令 · 472 个测试 · Next.js 看板

---

## 1. 真问题：求职的卡点不在信息，在人

市面上的 AI 求职工具几乎都在做同一件事——帮你**投得更多更快**：海投、关键词匹配、套模板生成话术。但我自己找实习时发现，真正卡住我的根本不是"信息不够"：

- 我筛出了 37 个高分岗、定制了 19 份简历，**却一个都没投出去**。
- AI 生成的打招呼话术，**我每次都要改**——它不像我说话。
- 两个 offer 摆在面前，我不知道**按什么标准选**。

这些卡点，海投工具和套模板的工具一个都解决不了。因为它们停在**行为层**（你做了什么），没碰到**人**（你为什么这么做）。

## 2. 核心洞察：从"行为层"到"认知层"

这是整个产品的灵魂，也是和市面工具的根本区别：

| | 行为层工具（市面主流） | JobPilot |
|--|----------------------|----------|
| 建模什么 | 你**怎么做**（投递、点击、偏好） | 你**怎么想**（决策方式、盲区、价值排序）+ **怎么说**（语言风格） |
| 给你什么 | 更多岗位、通用话术 | 针对你这个人的诊断、像你写的话术、扛得住追问的建议 |
| 举例 | "推荐你投这 50 个岗" | "你 19 份简历 0 投递不是懒，是你'在乎的事用了过高标准'——先允许自己投个不完美的版本" |

**最锋利的能力**：它能抓到「你说的」和「你做的」之间的矛盾。
> 例：我把"996"列为 deal-breaker，但认知模型显示我在乎的事会自我压榨。所以选 offer 时它会提醒我：*这个岗你会很投入，正因如此要替自己守住边界，否则没人帮你踩刹车。* 关键词匹配给不了这种洞察。

## 3. 关键产品决策与取舍

> 每一个都是主动选择，不是默认。这是这个项目最想展示的部分。

| 决策 | 取舍逻辑 |
|------|---------|
| **不做自动投递、不写爬虫** | 投递不可逆 + 平台反爬；守住合规边界，定位"我们生成、你来发"。功能克制换信任与安全。 |
| **行为层 → 认知层** | 接入认知模型（怎么想）+ 语言样本（怎么说），差异化护城河；代价是深度绑定单用户。 |
| **计划/跟进用确定性逻辑，不烧 LLM** | "本周该投哪几个"能用规则算就别调 API——省成本，且每条建议都能指回数据、扛得住"凭什么"。 |
| **两段式打分** | 免费启发式给全部岗位粗筛，只对 top N 调 API 精评。一次跑完成本可控。 |
| **简历定制 patch 原 docx，不重新生成** | 用 difflib 把改动补丁回原文件，保留字体排版；技能白名单防 AI 膨胀未声明的能力。 |
| **不急着做多用户** | 现在最强的个性化恰恰来自深度绑定一个人；过早通用化会把它稀释成市面上又一个普通工具。先验证对一个人有用。 |
| **AI 可选降级** | 没有 API key 时走启发式 / 导出 prompt，基本功能不瘫。 |
| **军师建议先认可再诊断、不灌鸡汤** | 被拒时给建设性复盘而非空安慰——尊重用户，话术每句扛得住追问。 |

## 4. 三层架构

```
陪伴层   军师：chat（多轮+长期记忆+主动跟进）· advisor（诊断）· plan（周计划）· ask（答疑）
          —— 不只是工具，是陪跑
个性层   你声明的偏好（硬规则）+ 认知模型（怎么想）+ 语言样本（怎么说）
          —— 差异化在这一层
数据层   多渠道找岗（WebSearch / 小红书 / GitHub）+ 两段式 AI 打分 + 投递追踪
          —— 基础设施，人人都有
```

**"声明" vs "推断"的分工**（一个被反复想清楚的设计）：
- 你**声明**的偏好（城市、deal-breaker、不堆 buzzword）= **硬规则**，军师必须遵守，优先级高于推断。
- **推断**的认知（你实际怎么决策）= **理解层**，帮军师调整说话方式、识别你卡在哪。
- 两者的**矛盾**（说的 vs 做的）= 最有价值的洞察。

## 5. 结果与现状

- **真实跑通**：多渠道搜集 349 个岗位 → AI 打分 → 筛出 37 个高分岗；端到端 `pipeline-all` 一条命令跑完搜索→打分→定制→话术→日报。
- **对一个真实用户（我自己）产生了非泛泛的价值**：它对我 0 投递的诊断不是"加油快投"，是命中我决策方式的"你收敛了标准但没给自己启动许可"。
- **工程**：27 个 CLI 命令、472 个测试、CI（GitHub Actions + 覆盖率）、Next.js 看板部署在 Vercel（脱敏只读快照）。

## 6. 诚实的边界与下一步

- 现在是**深度单用户**阶段。多用户的工程不难（数据层已按用户隔离），真正的难题是**冷启动**：陌生用户怎么快速获得这种认知深度。
- 我的思路是**渐进式深度**：新用户不做心理测评，只填 5 分钟问卷 + 给几段自己的话术；然后**越用越懂你**——每次对话沉淀认知信号、每次改话术系统更像你、每次投递反馈校准判断。它不一上来就完美，而是**像一个跟了你三个月的人**。
- 我刻意**没有**急着实现多用户——因为想清楚冷启动之前贸然通用化，会毁掉产品最强的地方。
